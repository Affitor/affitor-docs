`GET /programs/{program_id}/customers` lists the customers partners brought you, newest first, as your dashboard lists them: the masked email, the partner, the stage and what they spent. It returns no contact details.

```http
GET https://api.affitor.com/api/v1/programs/{program_id}/customers
```

## Authentication

Send a live program API key as a Bearer token: `Authorization: Bearer <key>`. The key must have **Full access** and its read tick (**Can use the read API**) on. See [Brand API](/docs/api-reference/brand-api) for which keys can read.

## Parameters

| Parameter | In | Type | Required | Notes |
|---|---|---|---|---|
| `program_id` | path | string | Yes | The key's own program id, or me. |
| `status` | query | string | No | Only customers at this stage. One of `lead`, `conversion`. |
| `limit` | query | integer | No | 1 to 100, default 50. |
| `cursor` | query | string | No | next_cursor from the previous page; bound to this route, program and filters. It is an offset in a stable newest-first order: a row added while you page can appear twice, never be skipped. |

This list is paged: pass `limit` (1 to 100, default 50) and, for the next page, the `next_cursor` of the previous answer as `cursor`. `next_cursor` is `null` on the last page. A cursor works only with the same route, program and filters.

## Response

```json
{
  "data": [
    {
      "id": "9902",
      "email_masked": "j***@example.com",
      "status": "conversion",
      "partner": { "id": "5531", "name": "Jamie Lee" },
      "total_spent": { "amount": 9800, "currency": "USD" },
      "purchases": 2,
      "first_interaction_at": "2026-11-03T08:00:00.000Z",
      "last_purchase_at": "2026-11-21T14:03:00.000Z",
      "created_at": "2026-11-03T08:00:00.000Z"
    }
  ],
  "next_cursor": null
}
```

### Fields

| Field | Type | Always present | Notes |
|---|---|---|---|
| `id` | string | Yes |  |
| `email_masked` | string or null | Yes |  |
| `status` | string | Yes | `lead` or `conversion`, the stage the dashboard shows. |
| `partner` | object or null | Yes | The partner who brought the customer, with the id the [Partners](/docs/api-reference/brand-api-partners) list uses. |
| `total_spent` | Money object or null | Yes | Spent with the partner in USD (the currency sales are recorded in since the money-basis cutover). null when the customer's first purchase predates that cutover, so the amount's currency cannot be proven. |
| `purchases` | integer | Yes |  |
| `first_interaction_at` | string or null | Yes |  |
| `last_purchase_at` | string or null | Yes |  |
| `created_at` | string or null | Yes |  |

## Errors

Errors use one shape with a `code` and a `request_id`. The codes this endpoint can return:

| Status | `code` | When |
|---|---|---|
| 400 | [`invalid_request`](/docs/api-reference/brand-api#errors) | A parameter is unknown, repeated, malformed or out of range. `param` usually names it |
| 401 | [`invalid_key`](/docs/api-reference/brand-api#errors), [`wrong_key_type`](/docs/api-reference/brand-api#errors), [`key_revoked`](/docs/api-reference/brand-api#errors) | The key is missing, unknown, not a live program key, disabled or retired |
| 403 | [`insufficient_permission`](/docs/api-reference/brand-api#errors) | The key is tracking-only or its read tick is off |
| 404 | [`not_found`](/docs/api-reference/brand-api#errors) | The program in the path is not the key's own program |
| 500 | [`internal_error`](/docs/api-reference/brand-api#errors) | Retry with backoff; if it keeps failing, send us the `request_id` |
