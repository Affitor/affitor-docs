Every Brand API v1 error has one shape and an HTTP status. Branch on `error.code`; `error.message` is written for people and can change.

```json
{
  "error": {
    "code": "invalid_request",
    "message": "limit must be an integer from 1 to 100.",
    "param": "limit",
    "doc_url": "https://affitor.com/docs/api/errors#invalid_request",
    "request_id": "req_8Fq2Lk0Zt7Wm3Nd9Yb4Hc6"
  }
}
```

| Field | What it is |
|---|---|
| `code` | One of the codes below |
| `message` | What went wrong, in words |
| `param` | The query parameter that caused it, when one did |
| `doc_url` | This page, at the code's section |
| `request_id` | The same value as the `X-Request-Id` response header. Send it when you contact us |

Errors of the tracking endpoints (`/api/v1/track/...`) use a different shape: see [Errors & Troubleshooting](/docs/api-reference/errors).

## Codes

| Code | Status | Retry? |
|---|---|---|
| [`invalid_request`](#invalid_request) | 400 | Not unchanged |
| [`invalid_key`](#invalid_key) | 401 | Not until the key changes |
| [`wrong_key_type`](#wrong_key_type) | 401 | Not until the key changes |
| [`key_revoked`](#key_revoked) | 401 | Not until the key changes |
| [`insufficient_permission`](#insufficient_permission) | 403 | Not until the key's permission changes |
| [`not_found`](#not_found) | 404 | Not unchanged |
| [`conflict`](#conflict) | 409 | Not returned yet |
| [`rate_limited`](#rate_limited) | 429 | Not returned yet |
| [`internal_error`](#internal_error) | 500 | Yes, with backoff |
| [`unavailable`](#unavailable) | 503 | Not returned yet |

## invalid_request

The request can't be read. `param` names the query parameter when one caused it. Causes:

- a query parameter the route doesn't take;
- `limit` outside 1 to 100;
- a `cursor` that isn't one the API gave you;
- a parameter sent more than once;
- an id that isn't a positive whole number;
- a value outside the allowed list (for example a `status` that isn't `lead` or `conversion`);
- a date window with too many rows: ask for a smaller window.

Fix the request using `message`, then send it again.

## invalid_key

No usable key: the `Authorization: Bearer <API key>` header is missing, or the key matches no program. Send a live program API key from **Program settings** › **Developers** › **API keys**.

## wrong_key_type

The key is real but can't call the Brand API: a test key (`aff_test_`) or an agent key. Use a live program API key.

## key_revoked

The key no longer works: it was disabled, or it was retired after a rotation (the message gives the date). Turn the key back on, or use the new key, in **Program settings** › **Developers** › **API keys**.

## insufficient_permission

The key works but can't read: it is a **Tracking only** key, or **Can use the read API** is off for it. Use a **Full access** key and tick **Can use the read API** in **Program settings** › **Developers** › **API keys**.

## not_found

The thing in the path doesn't exist for this key: an unknown partner, or a program other than the key's own. A key reads only its own program, so another program's id answers `not_found`, never `insufficient_permission`. Check the id you sent; `me` always means the key's program.

## conflict

Not returned yet.

## rate_limited

Not returned yet: the Brand API doesn't refuse requests for volume today. Once the key is accepted, every answer carries `RateLimit-Policy` and `RateLimit` headers that show the budget and what is left of it.

## internal_error

Something failed on our side. Retry with backoff. If it keeps failing, contact us with the `request_id`.

## unavailable

Not returned yet.
