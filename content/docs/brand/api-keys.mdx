Affitor has one self-serve credential: the **program API key**. It authenticates server-side tracking calls for a single program, you manage it yourself from the dashboard, and it is the key every integration guide, SDK, CLI command, and agent skill refers to.

## The program API key at a glance

| Property | Value |
|---|---|
| Prefix | `aff_` |
| Scope | One program. A key authenticates calls for the program it belongs to and nothing else. |
| Sent as | `Authorization: Bearer <key>` |
| Created | Automatically, when the program is created. You replace it at any time. |
| Visibility | Shown in full exactly once, at the moment it is generated. Masked everywhere after that. |

```bash
curl -X POST https://api.affitor.com/api/v1/track/sale \
  -H "Authorization: Bearer $AFFITOR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "transaction_id": "txn_abc123", "customer_key": "user_123", "amount_cents": 9999 }'
```

:::note

Keys issued before the short prefix was introduced do not start with `aff_`. Authentication is an exact match on the key itself, so those keys keep working; regenerating gives you an `aff_` key.

:::

## Where to find it

1. Select **Settings** in the left menu of your program.
2. Under **Developer**, select **API Key**.

The key displays masked, for example `aff_abcdefgh****wxyz`. The full value is revealed once — right after it is generated — so copy it then and store it server-side:

```bash
# .env — server-side only. Never ship this key to the browser.
AFFITOR_API_KEY=YOUR_PROGRAM_API_KEY
```

If you no longer have the current value stored anywhere, you cannot recover it: generate a new one instead. The full click-path, including the one-time reveal, is in [Manage program settings and your API key](/brand/settings).

Program read endpoints never return the raw key. They expose `api_token_masked` only, so a leaked read response cannot be used to forge tracking calls. At rest the key is stored as a SHA-256 hash and matched by hash on every request, so the raw value is never persisted in readable form after issuance.

## Which calls need it

| Call | Key required |
|---|---|
| `POST /api/v1/track/sale` | Yes |
| `POST /api/v1/track/refund` | Yes |
| `POST /api/v1/track/lead` — server mode | Yes. Sending the key is what makes the signup a server-attributed lead. |
| `POST /api/v1/track/lead` — browser mode | No. The click cookie proves attribution instead. |
| `POST /api/v1/track/click` | No. Click tracking is public. |

Every endpoint above is documented in the [API reference](/api-reference/overview).

## Replace a key

Regenerate the key if it may have leaked, if it was committed to a repository, or as routine hygiene when someone with key access leaves.

1. In **Settings** → **API Key**, regenerate the key.
2. Copy the new value from the one-time reveal.
3. Update `AFFITOR_API_KEY` everywhere the old key was stored — deployment environment, secret manager, CI — and redeploy.

:::caution

Regenerating invalidates the old key immediately. Every integration still sending it starts receiving `401` until you deploy the new one, so update your environment before rotating in production.

:::

## When Affitor asks you to replace a key

Affitor can mark a specific program key for mandatory rotation — for example after the key was exposed outside your control. While it is marked, the key keeps authenticating requests, so tracking is never interrupted, but every response tells you to replace it:

- `Deprecation` and `Sunset` headers, plus a `Link` header pointing at the error reference
- a `warnings` array in the JSON body carrying the code `api_key_rotation_required` and the deadline

After the deadline the key stops working and the same code comes back as a `401`. Branch on the code, not on the message text. The full header and body shapes are in [`api_key_rotation_required`](/api-reference/errors#api_key_rotation_required).

Replacing the key clears the flag: regenerate it in **Settings** → **API Key** and the warnings stop.

## Agent API keys

Separately from program keys, Affitor issues **agent API keys** (prefix `agt_`) to approved tools that read and update programs on a brand's behalf through the `/api/agent/v1/...` endpoints.

These are issued by Affitor — there is no endpoint to create one yourself, and a program API key does not authenticate agent endpoints. If you are building an integration that needs one, [contact support](/support/contact).

If you only want an AI coding agent to install tracking for you, you do not need an agent key: point it at [skill.md](https://docs.affitor.com/skill.md) with your program API key in the environment. See [Agent Integration](/api-reference/agent-integration).

## Which key do I send?

| Your task | Key to send |
|---|---|
| Track a conversion — clicks, leads, sales, refunds | Program API key (`aff_`), from **Settings** → **API Key** |
| Read or update programs on a brand's behalf via `/api/agent/v1/...` | Agent API key (`agt_`), issued by Affitor |
