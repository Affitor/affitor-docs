Everything you configured in the [setup wizard](/docs/brand/quickstart/setup-program) stays editable after launch, and Settings also hold the API key that every server-side [tracking call](/docs/api-reference/overview) authenticates with. This guide shows where each setting lives, how to change terms safely, and how to rotate the key with the shortest possible gap in tracking.

## What lives in Settings

Settings belong to the program selected in the program menu. Open the program menu (your program's name at the top of the left menu, or in the top bar on smaller screens) and choose **Program settings**. The same menu also has **Members** (only for people who can manage members) and **Billing**. Everything on the Settings pages applies to that program.

![The program menu, opened from the program name at the top left: the current program with Program settings, Members and Billing, and beside it your programs with their status and Create program](/docs/brand/program-menu.png)

**Program settings** include the setup pages and **Partner links**, which controls the destinations and number of additional links partners can create:

| Page | What you edit there |
|---------|--------------------|
| **Business** | Business name, website, program URL (your public page), tagline and logo, with a **Branding** section for how your program page looks in the marketplace. **Program ID** is shown read-only with **Copy** |
| **Commission** | Commission type, rate and duration, attribution window, hold period, and how new partners join (**Approve all** or **Review each**) |
| **Tracking** | Click and signup (lead) tracking on your website, and the **Partner link parameter** (`?via=` or `?aff=`) |
| **Partner links** | [Allowed domains and pages, an additional-link limit per partner, and the preferred link format](/docs/brand/partner-links) |
| **Payments** | How sales are counted: two cards, **Stripe** and **Server API**, each with its own state. Either one is enough |
| **Go live** (**Status** once the program is live) | What the program still needs to go live, and its live state |

The rest of the Settings menu:

| Group | Item | What it is |
|---------|------|------------|
| **Developers** | **API keys** | The per-program secret key for server-side tracking calls, and the line for an AI coding agent |
| **Team** | **Members** | Who can work on the program |
| **Billing** | **Invoices** | Platform-fee invoices |
| **Explore** | **Refer a brand** | Your link for referring brands to Affitor, **Invite via email**, and the brands you referred ([how it works](/docs/partners/quickstart/get-your-referral-link#refer-a-brand-to-affitor)) |

Your own settings are not part of a program. To change your profile, sign-in or payout details, open the **⋯** menu next to your name at the bottom of the left menu and choose **Your account**: it has **Profile**, **Login and security** and **Payouts**.

## Step 1: Edit program terms after launch

Programs evolve — rates get adjusted, branding gets refreshed, approval policies tighten or loosen. None of this requires recreating the program.

1. In the program menu, choose **Program settings**.
2. Open the page you want to change: **Commission** for the rate, hold period and how new partners join, or **Business** for the business name, website, logo and branding.
3. Make the change and save. On **Commission**, once terms are saved, select **Set new terms** before you change them.

:::tip

The **Commission** page sets your program-wide default. To pay different rates to different sets of partners, [organize partners into groups](/docs/brand/groups) — each group carries its own commission policy.

:::

## Step 2: Find your API key

Every server-side call to the tracking API — sales, refunds, and server-mode leads — authenticates with a Bearer token that is unique to your program. Integrations, SDKs, the CLI's tracking setup, and AI agents all use this same key. CLI commands that create or list programs act as your account instead, and authenticate with your CLI login.

1. In the program menu, choose **Program settings**.
2. Under **Developers**, select **API keys**.

The dashboard displays the key masked, and no read returns the full value. It is revealed exactly once — in the response to an owner's **Generate** or **Regenerate** action on the **API keys** page. If you no longer have the current key stored anywhere, you can't recover it from the dashboard; regenerate it instead (Step 3).

Store the key as a server-side environment variable:

```bash
# .env — server-side only. Never ship this key to the browser.
AFFITOR_API_KEY=YOUR_PROGRAM_API_KEY
```

:::note

The **API keys** page also gives you a one-line instruction for an AI coding agent, under **Set up with your AI agent**. It points the agent at [skill.md](https://affitor.com/docs/skill.md) with your program ID and key variable, so the agent can install tracking for you — see [Agent Integration](/docs/api-reference/agent-integration).

:::

## Step 3: Regenerate the key

Rotate the key if it may have leaked, if it was committed to a repository, or as routine hygiene when a team member with key access leaves.

Only a **workspace owner** can regenerate a program key. A member who tries is refused, so ask an owner to run it and to hand you the new value through your secret manager.

:::caution

The two keys never overlap. Regenerating replaces the key in place, and you receive the new value only in the regenerate response, so you cannot deploy it in advance. Between the regenerate and the redeploy, every integration still sending the old key gets `401` responses. Copy the new value before you close the reveal — it is shown one time only.

:::

1. Line up every place `AFFITOR_API_KEY` is stored — deployment environment, secret manager, CI — so you can update them straight away.
2. In **Settings** → **API keys**, regenerate the key. The old key stops working at that moment.
3. Copy the new key from the one-time reveal, update those places, and redeploy.

## Verify it worked

Send a test-mode sale with the new key. It authenticates exactly like a real sale but creates no commission and no platform fee.

Request — `POST /api/v1/track/sale`:

```bash
curl -X POST https://api.affitor.com/api/v1/track/sale \
  -H "Authorization: Bearer YOUR_PROGRAM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "additional_data": { "test_mode": true },
    "amount_cents": 9999,
    "currency": "USD",
    "sale_type": "payment"
  }'
```

Expected response:

```json
{
  "success": true,
  "message": "Test sale event tracked successfully",
  "data": {
    "eventId": 789,
    "programId": 1,
    "test_mode": true
  }
}
```
