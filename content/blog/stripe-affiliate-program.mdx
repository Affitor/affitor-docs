Stripe has no affiliate feature of its own: no referral links, no partner accounts, no commission ledger. Every tool below adds that layer on top of your Stripe account, and they differ on three things: what they read from Stripe, how they charge you, and where the price jumps.

## How these tools connect to Stripe

There are two ways an affiliate tool gets your Stripe data, and it is worth knowing which one you are approving.

**A Stripe App.** PromoteKit, Endorsely, Rewardful, FirstPromoter, Partnero, Tolt and Trackdesk install from the Stripe App Marketplace. Before you install, Stripe shows the exact objects the app can read or change, and the table above summarizes those lists. Most of them ask for write access to coupons and promotion codes so they can create a partner's discount code in Stripe for you. Trackdesk asks for the least: read access to customers and events. [Rewardful's help center](https://help.rewardful.com/en/articles/2213091-how-does-rewardful-use-my-stripe-account) describes how it uses its access: it reads the `referral` attribute in customer metadata, paid invoices and refunds, and adds affiliate and commission details back to that metadata.

**An OAuth connection.** Affitor connects through Stripe Connect OAuth, using Stripe's standard read_write scope. From the connected account it handles completed Checkout Sessions, paid invoices for subscription renewals, refunds (the commission is reversed) and disputes.

With Affitor you keep charging customers in your own Stripe account; Affitor never becomes the merchant of record.

If some revenue does not go through Stripe Checkout, Affitor also takes sales from your server with `POST /api/v1/track/sale`, which works with any payment provider. The [payment tracking docs](https://affitor.com/docs/brand/tracking/payment-tracking-stripe) cover both paths.

## How to set up Stripe affiliate tracking on Affitor

Four steps, and the last one tests the chain before a partner sends real traffic. Affitor attributes each customer to the partner whose click first brought them in, within the attribution window you set.

## Step 1: Create your program and set the commission

Create a program at [affitor.com/welcome](https://affitor.com/welcome), or from your project root:

```bash
npx affitor login
npx affitor init
```

`init` creates the program and writes its API key to `.affitor/.env`, which it adds to `.gitignore`. Then open the program in the dashboard and set the commission on its Default partner group: that is the rate partners are paid on every sale, and the test in Step 4 needs it. The [CLI commands reference](https://affitor.com/docs/brand/cli/commands) lists every flag.

## Step 2: Connect Stripe

In your program's settings, click **Connect Stripe** and approve the Stripe Connect authorization. From then on Affitor receives your checkout, invoice, refund and dispute events.

Affitor matches each sale to a partner using the click ID, the email captured at signup, the Stripe customer ID or your own customer key, whichever it finds. To make the match reliable, pass your user ID and program ID as metadata on the Checkout Session:

```js title="server/create-checkout.js"
// clickId comes from the affitor_click_id cookie.
// customer_key is your internal user ID: send the SAME value you send at signup.
const session = await stripe.checkout.sessions.create({
  line_items: [{ price: 'price_xxx', quantity: 1 }],
  mode: 'subscription',
  success_url: 'https://yoursite.com/success',
  cancel_url: 'https://yoursite.com/cancel',
  metadata: {
    affitor_click_id: clickId,
    affitor_customer_key: currentUser.id,
    program_id: 'YOUR_PROGRAM_ID',
  },
  // Repeat the values here so renewal invoices stay attributed.
  subscription_data: {
    metadata: {
      affitor_click_id: clickId,
      affitor_customer_key: currentUser.id,
      program_id: 'YOUR_PROGRAM_ID',
    },
  },
});
```

Prefer not to connect Stripe? Report each sale from your own Stripe webhook handler with `POST /api/v1/track/sale` instead, as the [payment tracking docs](https://affitor.com/docs/brand/tracking/payment-tracking-stripe) show. Use one path, not both.

## Step 3: Add click and signup tracking

Add the tracker to every page where partner traffic can land. It reads the `?aff=` parameter and stores the click in a first-party cookie:

```html
<script src="https://api.affitor.com/js/affitor-tracker.js"
  data-affitor-program-id="YOUR_PROGRAM_ID">
</script>
```

When a signup succeeds, tell Affitor who signed up, using the same customer key you put in the Stripe metadata:

```js
window.affitor.signup(currentUser.id, currentUser.email);
```

Add both by hand. Replace `YOUR_PROGRAM_ID` with your real program ID, which the dashboard shows (and `.affitor/config.json` holds if you used `init`). The [tracking overview](https://affitor.com/docs/brand/tracking/tracking-overview) explains how the pieces fit.

## Step 4: Run a test click, signup and sale

Run the test from your project root. It uses the API key from `.affitor/.env`, or pass one with `--api-key`. The `--json` flag keeps it from editing any of your files:

```bash
npx affitor onboard --json
```

It fires a synthetic click, signup and sale through Affitor's attribution pipeline, then polls the program's readiness and prints a summary:

```json title="npx affitor onboard --api-key aff_xxx --json"
{
  "program_id": "430",
  "steps": [
    { "step": "detect", "status": "ok", "detail": "framework=next-app, provider=stripe" },
    { "step": "browser_tracking", "status": "skipped", "detail": "json mode" },
    { "step": "server_sale", "status": "manual", "detail": "json mode (no auto-edit)" },
    { "step": "env_key", "status": "manual", "detail": ".env: json mode (no auto-edit)" }
  ],
  "integration_verified": true
}
```

`integration_verified: true` means the program passed its readiness checks: profile, commission, tracking, and a live event. A real click or sale on the program can also satisfy those checks, so `true` on its own does not prove the test sale was attributed. Check the test chain directly in the readiness response, with the same API key:

```bash
curl -s https://api.affitor.com/api/v1/programs/me/readiness \
  -H "Authorization: Bearer $AFFITOR_API_KEY"
```

`gates.live.test_chain.sale` should read `"attributed"`. If the summary says `false`, `blocker` and `next_action` name the first check to fix. Fix it and run the test again until the sale step reads attributed. The test rows are flagged as tests: no partner earns from them, they create no platform fee, and they stay out of your revenue numbers. You can run the test 10 times per program per hour.

The synthetic chain runs inside Affitor. It does not go through your site's signup call or Stripe's webhook delivery to your account, so it cannot prove those two pieces work.

When the test sale reads attributed, click **Go live** on your program's Share Program page. The program becomes active and gets its marketplace listing. Before you invite partners at scale, have one partner send a real click and make one real purchase through their link, then check that the sale and its commission show up in your dashboard. The [CLI quickstart](https://affitor.com/docs/brand/cli/quickstart) covers the same commands.
